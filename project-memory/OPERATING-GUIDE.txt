JOB-APPLICATION PROJECT MEMORY — HOW TO USE IT

FOR LOHITH
Open a new chat in this project folder and say:
  Read AGENTS.md, run the project-memory startup, and show me where we are and
  the next checkpoint. Use the saved plan. Do not begin changes until we discuss it.

Speak normally after that. The agent keeps the records up to date. Your feedback
is not an instruction to rebuild everything. Your acceptance finishes a checkpoint.
Visible status: project-memory/cache/status.html (generated by view).
It reloads every five seconds. Hooks and record updates regenerate it. Its displayed
generation time tells you how current it is; a stopped host cannot update it.

COMMANDS (PowerShell, from the project root)
  .\scripts\project-memory.ps1 start
  .\scripts\project-memory.ps1 show checkpoint-memory
  .\scripts\project-memory.ps1 search skills

Python alternative: python scripts/project_memory.py start (no package installation).
The launcher uses bundled Python if present, otherwise PATH Python. Python 3.11+;
no network, model API or extra dependency is needed.

UPDATING A RECORD (AGENT RESPONSIBILITY)
Read show ID and retain its revision. Write the revised JSON in
project-memory/scratch/update.json, keeping its links/sources and adding new ones.
Run put --file project-memory/scratch/update.json --expected-revision N --reason
"What changed and why". A stale revision is rejected: reread rather than overwrite.
If focus changes, update project.focus with its own revision. Refresh view.
Never edit prior revision files. Commit named records/code for this one purpose.

Example new change record (example only, not a saved candidate fact):
{
  "id": "change-3d-evidence", "kind": "change", "status": "proposed",
  "title": "Include newly described 3D work",
  "summary": "Lohith supplied missing 3D experience; inspect selection impact before redesigning anything.",
  "body": "Save actual facts, reason, affected scope and source here.",
  "links": [{"rel": "affects", "to": "module-canonical"}]
}
Create uses expected revision 0. Run impact on the affected existing records. It
follows recorded depends_on, uses and implements links, not all possible semantic
dependencies. Inspect code/sources too. Explain affected checkpoints to Lohith,
agree the change, then reopen only affected work as needs_review. Save the paused
position and next action so a design discussion does not lose the original task.

Statuses: planned / in_progress / review / accepted / needs_review / blocked /
deferred; reference / historical / superseded for source/decision records.
Blank means untouched. Accepted requires acceptance.user_statement (agents must
also give its source). This is provenance, not an unforgeable approval system.

COMMIT HABIT
One coherent change per commit, including its record update. Example title:
  memory(change-3d-evidence): record 3D evidence and affected selection work
Inspect git diff and git diff --cached. Stage named paths only. Never bundle
unrelated changes, .env, raw logs, generated resumes or cache. Do not push unless
asked. Raw read/tool operations produce events, not a commit per operation.

STORAGE
records/ID/000001.json etc: immutable versioned records; highest revision is current.
sources/: exact imported sources. Current rules and latest explicit user intent
override historical instructions. Do not edit original agreements or snapshots.
cache/memory.sqlite3: disposable relational search/graph index. Rebuild recreates
it from records; the database is not the only copy of the memory.
events/YYYY-MM-DD.jsonl: local activity history, excluded from Git. Back up this
directory too when moving machines if raw observations are needed.
cache/status.html: generated human view, never authoritative.

SOURCE CHANGES
source ID checks the saved hash before returning exact text. To preserve a new
version: import-source PATH --id NEW-ID --snapshot, add a supersedes link and update
affected records. Old revisions remain available via show ID --revision N. Source
sections point to one original instead of copying its full body into each record.

OBSERVATIONS AND CODEX
scripts/install_memory_hooks.py writes project .codex/hooks.json. It never changes
trust/permissions or starts a model. Codex requires review/trust of project-local
hooks: use /hooks in Codex CLI to review them, without a trust-bypass flag. Start a
new session and run health. Until a non-synthetic event arrives, automatic recording
is unverified. Official behavior: https://learn.chatgpt.com/docs/hooks

Events: SessionStart, PreToolUse, PostToolUse, PreCompact, PostCompact, Stop,
Interrupt, SessionEnd. Startup/compaction load a bounded briefing. Tool events save
IDs, timestamps, tool name, command verb, input hash, explicit exit/error fields
when supplied, elapsed time if its start exists, and a transcript path. Raw prompts,
command bodies, outputs and secrets are not copied. Unknown outcomes stay unknown.
Hosted web tools and some special paths are outside coverage. This is continuity
and observation, not a sandbox. Decisions still require agent put/event calls.
Other terminal agents can use the CLI; their observation adapters are not installed.

RECOVERY
After interruption: start, doctor, timeline; inspect actual Git diff and unfinished
commands. Never blindly repeat potentially active side effects. Partial records/log
lines are reported; corrupt records cannot be overwritten as new. Inspect and
recover a damaged record from Git or a previous revision. Rebuild recovers a broken
SQLite cache. seed_project_memory.py deliberately refuses to reset a live project.

BOUNDARIES
The application quality is not accepted. Old worker controls remain unproved.
No hardcoded model, paid application run, submission, deployment or push is
authorized merely by opening a new chat. Explain the next task to Lohith first.
