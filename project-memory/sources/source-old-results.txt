# Coding controls and application visibility: test evidence

Purpose: check whether the agreed controls behave as promised. These examples do not establish resume quality or make the coding agent an independent authority over its own work.

## Step 1 — deliberate failures, before a real coding task

The input is a small local Python worker with predictable behavior. Expected outcomes come from the user's requirements: stop means stop; deadlines are enforced; only authorized files may change; a worker saying “done” does not override failed evidence.

| Input/action | Expected observable result | Actual result |
|---|---|---|
| Worker writes the required content in the allowed file | Content check passes and task completes | Pending |
| Worker writes wrong content but reports success | Content check rejects completion | Pending |
| Worker writes an unauthorized file | Scope check rejects completion and preserves the change for inspection | Pending |
| Worker gives an invalid result | Task fails with a specific reason | Pending |
| Worker sleeps beyond its deadline | Controller stops it and records timeout | Pending |
| Verification command sleeps beyond the deadline | Verification stops too | Pending |
| User requests stop during a worker or verification | Owned work stops; evidence remains available | Pending |
| A second managed task tries to write in the same workspace | It is refused while the first owns the workspace | Pending |
| Worker changes the task or its verification script | Completion is rejected | Pending |
| Windows process liveness is checked | The check does not terminate that process | Pending |

## Step 3 — application visibility

This concerns the resume application's own run: which stage is active, whether it is waiting for the writer or Jev, what has been saved, and what failed. Verification uses fake transports and saved data so it does not need a live resume-generation run.

Planned observable cases: successful response, cached response, provider error, hanging request, cancellation, and reading status/report after a stopped run. Result: pending.
